# V5.0 · 单人开发工作安排:优化冲刺(单人版)+ 后续开发路线

> 维护者:策划+开发(唯一人力) ｜ 日期:2026-07-14 ｜ 引擎:Godot 4.6.3 / GDScript
> 本案是 [`优化冲刺-2天2.5人-实施方案_V4.md`](优化冲刺-2天2.5人-实施方案_V4.md) 的**单人替代版**:美术与 UI 人力归零,全部代码仍由 Fable 5 编写。V4 的现状盘点(§一)、问题清单、砍量红线继续有效,本案不重复,只讲**单人怎么排**。

## 〇、一句话定位

> 单人 + AI 的瓶颈不是产能,是**你的注意力和判断力**。所以工作安排的核心是:**把你的时间全部留给"决策、验收、试玩、调参"**;把美术从"人画"改成"代码驱动 + 素材库";把节奏从"两天冲刺"改成"3 天稳定化 + 按周推进的路线图",每周有一个能给人看的构建。

## 一、单人 + Fable 5 的工作模型

### 1.1 你的时间只花在四类事上(每天 8h 的分配基准)

| 类别 | 占比 | 内容 |
|---|---|---|
| 试玩与调参 | ~40% | 真机跑局、记录体感、改 CSV、验证数值;这是策划本职,也是 AI 替代不了的部分 |
| 任务简报与验收 | ~30% | 给 Fable 5 开任务(每个 30 秒说清目标/文件域/约束/验收)、看 diff、真机验收 |
| 编辑器内操作 | ~15% | 摆放、截图判断光照/构图、素材导入确认——凡是"要用眼睛看"的 |
| 规划与记录 | ~15% | 维护 backlog 和 `进展-单人.md`(给下个 AI 会话的上下文,替代原来的队友沟通) |

### 1.2 AI 并行规则(防止自己把自己冲突了)

- **同一时刻最多 2 条工作流**:1 条**主线**(允许动玩法核心文件)+ 1 条**副线**(只做与主线文件域不相交的事:性能、tools、清理、UI 皮肤)。副线适合挂着自跑、午后统一验收的机械任务。
- **任务粒度 ≤ 半天**;超过半天先让 AI 帮你拆。
- **每个任务的提交门禁不变**:`--headless --import` 干净 → 相关 `tools/verify_*` 全绿 → `run_speedrun.bat` 20 秒全流程 → 你真机 2 分钟验收 → commit。新功能补 verify 脚本。
- **不要人肉写码**:不满意就把"哪里不对"说给 AI 重做,保持代码出处单一,否则一周后你自己都不知道哪段是谁写的。
- master 始终可玩;有风险的重构开分支,验收后再合。

### 1.3 每日节奏(默认模板)

| 时段 | 做什么 |
|---|---|
| 09:00-09:30 | 跑一遍昨日构建(速通模式+1 局正常局),定今日唯一目标,写进 backlog |
| 09:30-12:30 | 主线任务 ×2~3 个验收循环;副线挂机械任务 |
| 13:30-16:30 | 继续主线;每完成一项立即真机验证 + 小步 commit |
| 16:30-17:30 | 集成试玩:完整跑 1-2 局,数值体感和 bug 记进 `进展-单人.md` |
| 17:30-18:00 | 收尾提交、写明日三行清单;**每周五加:出包 + 录 30 秒 gif** |

> 每周五的构建+gif 是单人模式的生命线:它同时是里程碑验收、对外汇报素材、和你自己的动力来源。

## 二、美术与 UI 归零后的替代策略(逐项落位)

V4 里 B(美术)和 C(UI)的任务不是消失,而是换实现方式。原则:**能代码化的代码化,能用库的用库,都不行的砍。**

| 原任务(V4 归属) | 单人替代方案 | 结论 |
|---|---|---|
| 守门人房美术化(B, 6h) | **代码驱动**:Fable 5 照 `level_02_art.gd` 的栅格化方法给 boss_room 铺 Synty 地砖/墙/火盆/顶光(782 个 FBX 都在库里),你只负责看截图提意见 | 保留,约 0.5 天注意力 |
| 技能/buff/塔图标(B, 3h) | 用 **game-icons.net**(CC BY,单色 SVG,4000+)或 Kenney(CC0):下载一批 → Fable 5 写导入+染色管线(描边金框统一风格);记得在 README 加署名 | 保留,约 2h 注意力 |
| UI 9-slice 皮肤(B+C) | **全局 Theme 资源**:Fable 5 做一个"暗石底+金边+Noto 字体"的 `Theme`(StyleBoxFlat 程序化),一次性应用到选层/暂停/结算/失败/对话全部面板 → 统一感靠一致性而非手绘质感 | 保留,约 2h 注意力 |
| 结算面板战利品墙图标化(C) | 同上管线:物品图标从 game-icons 选 14 个映射到 `boss_drop_list.csv` | 保留 |
| 光柱/进度球/塔 VFX(B) | BinbunVFX 已在库 + GPUParticles 由 AI 写;你截图验收 | 保留,降半档 |
| 随从换模(B) | 16 个 Synty 角色现成,挑一个人形近战,AI 换引用即可 | 保留,15 分钟 |
| 全局光照统一(B) | AI 调 WorldEnvironment 参数 → 每轮给你出对比截图 → 你选 | 保留,迭代 2-3 轮 |
| 手绘高质量 UI 贴图、定制角色模型/动画 | 无替代 | **永久砍**(单人上限,接受) |

## 四、阶段 1:内容深化(第 2 周起,按周排)

> 阶段 0 交付的是"更完善的切片";后续开发的方向问题:**推荐走「从切片到可公开试玩的 Demo」**——把展示用假功能逐个变真,形成可重复游玩的循环。以下里程碑按推荐顺序排,每个都是独立可交付、可随时停的切口;做完一个,周五构建就多一个卖点。

| 里程碑 | 内容 | 预估 | 完成判定 |
|---|---|---|---|
| **M1 真选层难度**(强烈推荐先做) | 选层从纯展示变真:层数 → 怪物 HP/ATK/密度乘区(读 CSV 缩放,不改 SSOT 结构);通关解锁下一层;结算记录最高层。**这一步直接把"单局演示"变成"可重复的游戏循环"** | 1-2 天 | 打 3 层体感差异明显;失败有再试动机 |
| **M2 换装真生效 + 局间存档** | 重新接回被 V3 故意断开的 `Inventory.stats_changed → DamageCalculator.refresh_from_stats` 链(代码都在);守门人爆装跨局保留(JSON 存档)→ 配合 M1 形成"打高层→爆装→变强→更高层"的元循环 | 1-2 天 | 换上新弓 DPS 可见变化;重启游戏装备还在 |
| **M3 精英词缀池** | 现有熔火之外 +2~3 个词缀(奥术光束/冰霜新星/吸附任选),精英名条显示词缀名 | 1 天 | 遇到不同精英打法不同 |
| **M4 一局变化度** | 遭遇随机化(蓝图点位/组合抽样)+ 塔与进度球布点随机,让第 10 局仍有新鲜感 | 2 天 | 连打 3 局动线不完全相同 |
| **M5 第二守门人** | 用现成 Synty 角色+enemy_base 扩展做第二个 Boss(远程型),按层数轮换 | 2 天 | 两 Boss 打法区分 |
| **M6 音频/演出 pass** | Boss BGM 切换、低血心跳、通关 sting、选层界面氛围音 | 1 天 | 录屏听感完整 |

**决策点**:每完成一个里程碑,用周五构建找 1-2 个外部试玩者(前队友即可)玩 10 分钟,只看录屏不指导;下一个里程碑according试玩反馈可调序。

## 六、单人纪律(替代团队机制的部分)

1. **文档收口**:四份 `进展-*(角色).md` 停止维护(归档留证),新开一份 `进展-单人.md` 按天记三行:今天定了什么数值口径/改了什么/明天先做什么。它是 AI 会话间的记忆,也是你的决策日志。
2. **backlog 单一来源**:本文件 §三/§四 的任务表就是 backlog,完成打勾、砍掉划线,不另开看板。
3. **数值 SSOT 纪律不变**:改数值只动 `数值表/*.csv`,让 AI 同步 .tres/代码并跑 verify——单人更容易"顺手直接改代码",这是漂移的头号来源,务必守住。
4. **对抗单人盲区**:①每周五构建必发给至少 1 个外部人;②大的设计取舍(比如 M1 的难度曲线)先让 Fable 5 出 2-3 个方案对比再拍板,把 AI 当参谋用;③连续两天没有可玩进步 = 立刻砍范围,回到"每天一个可验证改进"。
5. **动力管理**:每天的"今日唯一目标"要小到必然完成;gif 存档目录按日期留,回头看得见进度。

## 七、风险与对策(单人特有)

| 风险 | 对策 |
|---|---|
| 判断疲劳:一个人又当策划又当验收,下午决策质量下降 | 上午做需要判断的(数值/设计),下午做机械验收和清理;重要取舍过夜再定 |
| 美术上限:代码驱动观感撞天花板 | 接受"统一 > 精美";若后续立项,美术外包点只需 3 类:UI 皮、角色、关键 VFX,现在的 Theme/图标管线都为可替换设计 |
| AI 大改造成回归 | verify 套件 + speedrun 是安全网;任何 autoload/玩法核心改动必须带回归;分支制 |
| 范围蔓延(没有队友互相刹车) | 每个里程碑开工前重读 §四的完成判定;新想法一律先写进 backlog 尾部,当天不做 |
| 单机器故障 | 每日 push;导出包同步网盘 |
